# บอร์ดติดตามงาน (Trello บน Google Sheets)

หน้าเว็บ (เช่น `/tracking`) ในโปรเจกต์ของผู้ใช้ ให้ทีมกับลูกค้าใช้ร่วมกันตอนประชุม/ส่งงาน —
เรื่องไหนรอใครตอบ เรื่องไหนกำลังทำ งานไหนติดเพราะคำถามข้อไหน รอบส่งงานไหนเสร็จกี่ %
ข้อมูลอยู่ใน **Google Sheet ของผู้ใช้** (แก้ในชีตตรงๆ ได้) ผ่าน **Apps Script Web App** — ไม่ต้องมี backend · ไม่ผูกกับฐานข้อมูลของแอป

ทำมาจากการใช้งานจริงที่ผ่านการตีกลับจากผู้ใช้หลายรอบ — ค่าเริ่มต้นในหัวข้อ "ค่าเริ่มต้นที่ผ่านการใช้งานจริง" มีเหตุผลรองรับ
เปลี่ยนได้ถ้าผู้ใช้เลือกต่างในขั้นสัมภาษณ์ แต่อย่าเปลี่ยนเองเงียบๆ

## ขั้นตอน

### 1. สำรวจโปรเจกต์ก่อนถาม

หาเองให้มากที่สุด จะได้ถามน้อย: เฟรมเวิร์ก + เวอร์ชัน · router (โหมด history?) · UI kit / design token / ไอคอน ·
modal · select · date picker · toast · ตัวจัดวันที่ที่มีอยู่ · ที่วาง lib (`src/lib/...`) · วิธีตั้งชื่อ env (`VITE_` / `NEXT_PUBLIC_` …) ·
ภาษาหน้าจอที่แอปใช้ · ภาษาของ comment ในโค้ด · ไฟล์ตั้งค่าโฮสต์ (`wrangler.*` · `vercel.json` · `netlify.toml` · `_redirects` · nginx) · มีหน้า `/tracking` อยู่แล้วไหม

### 2. สัมภาษณ์ผู้ใช้ (ใช้ AskUserQuestion · ใส่ "(แนะนำ)" ที่ตัวเลือกแรก)

ถามเฉพาะที่หาจากโค้ดไม่ได้ · รวบเป็น 1–2 รอบ (รอบละไม่เกิน 4 ข้อ) · ข้อไหนเดาจากโค้ดได้มั่นใจ ให้บอกค่าที่จะใช้แทนการถาม

**รอบ 1 — ตัวบอร์ด**
1. **ใครใช้ + ชื่อบนหัวหน้า** — เช่น "ติดตามงาน <ชื่อโปรเจกต์>" (แนะนำ) · ตั้งเอง
2. **path ของหน้า** — `/tracking` (แนะนำ) · `/board` · ตั้งเอง
3. **ชุดสถานะ (= คอลัมน์บอร์ด)** — มาตรฐาน 5: รอตอบ · รอทีมเรา · กำลังทำ · เสร็จแล้ว · พักไว้ (แนะนำ เหมาะกับงานที่ต้องถามลูกค้า) ·
   แบบสั้น 3: ต้องทำ · กำลังทำ · เสร็จแล้ว · ตั้งเอง
4. **ภาษาหน้าจอ** — ตามภาษาของแอป (แนะนำ · บอกว่าเจออะไร) · ไทย · English

**รอบ 2 — รายละเอียด**
5. **ช่องเสริม** (multiSelect · ค่าเริ่มต้นเลือกทั้งหมด) — กำหนดเสร็จ (deadline) · รอบส่งงาน · โมดูล · งานที่ติด (blocks) · ลิงก์เอกสาร
6. **เก็บชื่อคนทำ** — คอมเมนต์ + สร้าง/แก้ต้องพิมพ์ชื่อ ลากไม่ถาม (แนะนำ) · เฉพาะคอมเมนต์ · ไม่เก็บชื่อเลย
7. **Google Sheet จะอยู่บัญชีไหน** — Gmail ส่วนตัว (แนะนำ · ตั้ง "Anyone" ได้แน่) · Google Workspace ของบริษัท
   (เตือน: แอดมินบางที่ปิดการแชร์ออกนอกองค์กร → ตัวเลือก "Anyone" จะไม่มี และ "Anyone within โดเมน" ใช้ไม่ได้เพราะติด CORS)
8. **โฮสต์ที่ deploy** — ถามเฉพาะเมื่อหาไฟล์ตั้งค่าไม่เจอ (ใช้ตั้ง SPA fallback)

แล้วสรุปกลับสั้นๆ ว่าจะสร้างอะไร (path · สถานะ · ช่อง · กติกาชื่อ · ไฟล์ที่จะเพิ่ม/แก้) ก่อนลงมือ
ตอนสัมภาษณ์**อย่าเสนอระบบล็อกอิน** (ดูเหตุผลข้างล่าง) — ทำเฉพาะเมื่อผู้ใช้ขอเอง

### 3. วางโค้ดแกน

ก๊อป `assets/core/*.ts` ไปโฟลเดอร์ lib ของโปรเจกต์ (เช่น `src/lib/tracking/`)
- แก้ `tracking-config.ts` ให้อ่าน env ตามเฟรมเวิร์ก (มีตัวอย่างในไฟล์) + ประกาศ type ของ env ถ้าโปรเจกต์ใช้ (เช่น `vite-env.d.ts`)
- ปรับตามคำตอบสัมภาษณ์ → ทำตาม `references/customize.md`
- มี type `Tone` / `SelectOption` / ตัวจัดวันที่ของโปรเจกต์อยู่แล้ว → เปลี่ยนไปใช้ของโปรเจกต์ได้ · ปรับภาษา/สไตล์ comment ให้ตรงโปรเจกต์

### 4. ทำหน้า

ตาม `references/ui-spec.md` ด้วย component ของโปรเจกต์ — route สาธารณะ ไม่ต้องล็อกอิน ไม่ใช้ layout หลังล็อกอินของแอป
- Vue 3 + Tailwind → เริ่มจาก `references/vue/` แล้วแทน import · เฟรมเวิร์กอื่น → เขียนตาม spec ดู Vue แค่ logic ที่ยาก
- UI kit ไม่มี modal ที่ปิดด้วยคลิกนอกไม่ได้ / select ที่ล้างค่าได้ → เพิ่มเป็น prop แบบ opt-in (ค่าเริ่มต้นไม่เปลี่ยนพฤติกรรมเดิมของที่อื่น)
- ช่องเสริมที่ผู้ใช้ไม่เอา → ซ่อนในหน้าจอพอ ไม่ต้องตัดคอลัมน์ในชีต/Code.gs (ไม่มีผลเสีย และเปิดกลับง่าย)

### 5. วาง Code.gs + คู่มือ

ก๊อป `assets/Code.gs` และ `references/setup-guide.md` ไปไว้ในโปรเจกต์ (เช่น `scripts/tracking-apps-script/`)
แก้ตาม `customize.md` ถ้าเปลี่ยนสถานะ/ภาษา/กติกาชื่อ · แก้ชื่อ env/โดเมนในคู่มือให้ตรงโปรเจกต์

### 6. SPA fallback

ดูตารางใน `setup-guide.md` ข้อ 4 แล้วตั้งให้ตรงโฮสต์ — ไม่ตั้ง = วาง URL `/tracking` ตรงๆ / รีเฟรช แล้ว 404 ทั้งที่กดเมนูในแอปเข้าได้
(ผู้ใช้มักเจอหลัง deploy แล้วถามว่า "เป็นเพราะ SPA เหรอ" — ใช่)

### 7. ทดสอบโดยไม่แตะชีตจริง

- `node <base dir ของสกิล>/scripts/test-code-gs.js <path ของ Code.gs ในโปรเจกต์>` → ต้องได้ `ALL PASS`
  แก้ Code.gs (สถานะ · ภาษา · กติกาชื่อ) แล้วต้องอัป test ให้ตรงกติกาใหม่ด้วย ไม่ใช่ลบข้อที่พัง
- type-check / build ของโปรเจกต์ผ่าน
- เปิดหน้าโดย**ไม่ตั้ง URL** (โหมดข้อมูลตัวอย่าง — อยู่ในหน่วยความจำ รีเฟรชแล้วหาย) แล้วไล่เช็คลิสต์ท้าย `ui-spec.md` ใน browser จริง
- ⚠️ dev server ที่อ่าน env มี URL จริง → เปิดตัวแยกที่บังคับ URL ว่าง (Vite: `VITE_TRACKING_API_URL= npx vite --port 3001`) ·
  **ก่อนกดอะไรที่เขียนข้อมูล ตรวจว่ามีแถบ "ข้อมูลตัวอย่าง"** — เคยเผลอสร้างเรื่องทดสอบลงชีตจริงของผู้ใช้มาแล้ว
- เขียนลงชีตจริงเฉพาะเมื่อผู้ใช้สั่งให้ลองจริง — แล้วรายงานว่าสร้างอะไรไป (รหัส · ชื่อผู้บันทึก) ให้ผู้ใช้ตามลบได้

### 8. ส่งต่อให้ผู้ใช้

สรุปสั้นๆ ว่าผู้ใช้ต้องทำเอง (Claude เข้าบัญชี Google ของผู้ใช้ไม่ได้):
สร้างชีต → วาง Code.gs → ตั้ง Time zone → Run `setupSheets` → Deploy (Who has access = **Anyone**) → ใส่ URL ใน env → build ใหม่
- แก้ Code.gs ทีหลัง = Deploy → Manage deployments → ✏️ → **New version** (URL เดิม) — ทุกครั้งที่ Code.gs เปลี่ยน ต้องบอกผู้ใช้ชัดๆ ว่าต้องไปวางใหม่
- บอกด้วยว่าอะไร**ไม่ต้อง**ทำ (เช่น ไม่ต้องตั้งค่า Google Cloud Console · ไม่ต้องแก้ env ถ้า URL เดิม)

## ค่าเริ่มต้นที่ผ่านการใช้งานจริง (พร้อมเหตุผล)

- **แก้ไขได้เต็มแบบ Trello** ไม่ใช่หน้าดูอย่างเดียว — หน้าดูอย่างเดียวผู้ใช้ว่า "กระจอก" ใช้ประชุมจริงไม่ได้
- **ไม่มีระบบล็อกอิน** — เคยทำล็อกอิน Google (ID token + ตรวจโดเมนใน Apps Script) ใช้ได้จริง แต่ผู้ใช้ถอยกลับ
  เพราะต้องสร้าง OAuth Client ใน Google Cloud Console (ของบริษัท) เปลืองแรงเกินกว่าที่ได้ · ถ้าผู้ใช้ขอเองค่อยทำ และบอกให้ชัดว่าต้องตั้งค่าอะไรบ้าง
- **ชื่อพิมพ์เองทุกครั้ง ไม่เติมให้ ไม่จำ** ตอนคอมเมนต์ · สร้าง · แก้ไข — เติมชื่อเดิมไว้แล้วคนจะมักง่ายไม่แก้ชื่อตัวเอง ·
  **ลากย้ายสถานะ · ซ่อน ไม่ถามชื่อ** — ทำบ่อย ถามทุกครั้งน่ารำคาญ (บันทึก "ย้ายสถานะ" ยังเก็บเวลาไว้)
- **กล่อง (modal) คลิกนอก/กด Esc ไม่ปิด** ต้องกดปุ่มปิด/ยกเลิก — กันข้อความที่พิมพ์ค้างหาย
- **ตัวกรองค่าเริ่มต้น "ไม่เลือกอะไร"** · ทุก select มีกากบาทล้าง · มีปุ่มล้างทั้งหมด · การ์ดตัวเลขกดกรองได้
- **ข้อมูลอยู่ใน Google Sheets ตลอด** ต่อให้แอปมีฐานข้อมูลจริงแล้วก็ไม่ย้าย · **ชีตเริ่มว่าง** ไม่ทำไฟล์ข้อมูลตั้งต้น (ผู้ใช้สร้างเรื่องจากหน้าเว็บเอง)
- "ใครมีลิงก์ก็เข้าได้" ยอมรับได้สำหรับงานแบบนี้ — กันพื้นฐานไว้เงียบๆ (กันสูตร · ตรวจความยาว · โควตาต่อนาที) ไม่ต้องเตือนผู้ใช้ซ้ำๆ

## กับดักทางเทคนิค (เจอมาแล้วทั้งหมด)

- **POST ต้องส่ง `Content-Type: text/plain`** — Apps Script ตอบ CORS preflight (OPTIONS) ไม่ได้ · ส่ง `application/json` = ติด CORS (โค้ดแกนทำให้แล้ว)
- **Deploy ต้องเป็น "Anyone"** — "Anyone within <โดเมน>" ทำให้ fetch ข้ามโดเมนติด CORS (เบราว์เซอร์ไม่ส่งคุกกี้ Google) ต่อให้ผู้ใช้ล็อกอินบัญชีบริษัทอยู่ ·
  URL แบบ `script.google.com/a/macros/<โดเมน>/...` = deploy จากบัญชี Workspace — ถ้าไม่มีตัวเลือก Anyone ให้ deploy จาก Gmail ส่วนตัวแทน
- **กันแก้ทับ**: ส่ง `baseUpdatedAt` ทุกการแก้/ซ่อน · ช่อง `updatedAt`/`createdAt` ในชีตต้องเป็นรูปแบบตัวหนังสือ (`@`) ไม่งั้นชีตแปลงเป็นวันที่แล้วเทียบไม่ตรง
- **กันสูตร (formula injection)**: ข้อความขึ้นต้น `= + - @` เติม `'` ก่อนเขียนลงชีต · CSV ที่ดาวน์โหลดก็ต้องกัน (ทำไว้แล้วทั้งคู่)
- รหัส `T-###` นับจาก**ทุกแถวรวมที่ซ่อน** — ผู้ใช้อาจถามว่าทำไมไม่เริ่มที่ T-001 ให้ตอบว่ามีแถวเก่าซ่อนอยู่
- ข้อมูลตัวอย่างโหลดแบบ dynamic import — build จริงที่ไม่ตั้ง URL ต้องขึ้น "ยังไม่ได้ตั้งค่า" ห้ามโชว์ข้อมูลปลอมให้ลูกค้า
- เปลี่ยนคำของสถานะ/ประเภท/ความสำคัญหลังมีข้อมูลแล้ว → เพิ่มคำเก่าเป็น alias ใน `parseTrackingStatus` (แถวเก่าในชีตจะได้ไม่กลายเป็น "ไม่ทราบสถานะ")
- HTML5 drag & drop: การ์ดเป็น `div[role=button]` + `setData('text/plain', id)` (Firefox) · มือถือลากไม่ได้ → ตัวเลือกสถานะในกล่องรายละเอียด
- Playwright/การทดสอบอัตโนมัติ: date picker บางตัวคลิกตามพิกัดไม่ติด ให้คลิกที่ตัวเลขวันโดยตรง · modal มีแอนิเมชันปิด รอ element หายก่อนนับ

แนบไฟล์ (เก็บลิงก์ Drive) · แจ้งเตือนเรื่องเลยกำหนด (Apps Script time-driven trigger ส่งอีเมล) · หลายบอร์ด (แท็บชีตต่อบอร์ด) · ล็อกอิน Google
