# ปรับบอร์ดตามคำตอบสัมภาษณ์

ค่าเริ่มต้นของสกิล = ชุดสถานะมาตรฐาน 5 · ภาษาไทย · ช่องเสริมครบ · ชื่อตอนคอมเมนต์ + สร้าง/แก้
ตอบตรงค่าเริ่มต้นทั้งหมด → ไม่ต้องแก้อะไรในไฟล์นี้ ข้ามไปทำหน้าได้เลย

หลักใหญ่: **คีย์ภายใน (อังกฤษ) กับคำที่โชว์ (ภาษาผู้ใช้) แยกกัน** — เปลี่ยนคำง่าย เปลี่ยนคีย์/จำนวนกระทบหลายไฟล์
ทุกครั้งที่แตะ `Code.gs` → รัน `scripts/test-code-gs.js` และอัปข้อทดสอบให้ตรงกติกาใหม่

## สารบัญ
1. เปลี่ยนชื่อสถานะอย่างเดียว · 2. ใช้ชุดสถานะอื่น (จำนวน/ความหมายต่าง) · 3. ภาษาหน้าจอ English ·
4. ไม่เอาช่องเสริมบางช่อง · 5. กติกาเก็บชื่อ · 6. ชื่อบอร์ด / path

## 1. เปลี่ยนชื่อสถานะอย่างเดียว (จำนวน 5 เท่าเดิม)

แก้คำ **3 จุดให้ตรงกันทุกตัวอักษร** (ชีตเก็บเป็นคำ ไม่ใช่คีย์):
- `tracking-labels.ts` → `TRACKING_STATUS_LABEL` (+ `hint` ใน `TRACKING_STATUS_LEGEND` ถ้าความหมายเปลี่ยน)
- `Code.gs` → `var STATUS = { ... }` (ใช้ทำ dropdown ในชีต + คำที่เขียนลงชีต)
- `scripts/test-code-gs.js` → ข้อความ `'ย้ายสถานะ: … → …'` และคำสถานะในแถวทดสอบ
ชีตมีข้อมูลอยู่แล้ว → เพิ่มคำเก่าใน `STATUS_ALIASES` (`tracking-labels.ts`) และ Run `setupSheets` ใหม่ให้ dropdown เปลี่ยน

## 2. ใช้ชุดสถานะอื่น (เช่น 3 สถานะ: ต้องทำ · กำลังทำ · เสร็จแล้ว)

วิธีที่แก้น้อยสุด: **ใช้คีย์เดิมเท่าที่ความหมายตรง** แล้วตัดตัวที่ไม่ใช้ออก — เช่น `waiting_team` = ต้องทำ · `in_progress` · `done`
1. `tracking-types.ts` → union `TrackingStatus` เหลือคีย์ที่ใช้ (+ `'unknown'` ต้องคงไว้เสมอ — ใช้รับค่าพิมพ์ผิดในชีต)
2. `tracking-labels.ts` → `TRACKING_STATUS_LABEL` · `TRACKING_STATUS_TONE` · `TRACKING_STATUS_ORDER` · `TRACKING_STATUS_LEGEND` ·
   `TRACKING_BOARD_STATUSES` (= คอลัมน์ซ้าย→ขวา) · `isTrackingOpen` (สถานะไหนนับว่า "ยังค้าง") ·
   `isTrackingWaiting` (สถานะไหนขึ้นป้าย "ค้าง N วัน" — ถ้าไม่มีสถานะ "รอคำตอบ" ให้ใช้สถานะแรกของงาน)
3. `Code.gs` → `var STATUS` ให้คีย์ตรงกับข้อ 1 · ค่า fallback ตอนสร้างใน `readInput` (`['status', STATUS, 'waiting_client']`) ต้องเป็นคีย์ที่ยังมีอยู่
4. หน้าจอ → การ์ดตัวเลขที่กดกรองได้ (spec ข้อ 2) = สถานะที่ยังไม่จบ · การ์ดความคืบหน้าคงไว้ · ค่าเริ่มต้นสถานะในฟอร์มสร้าง
5. `tracking-mock.ts` → ข้อมูลตัวอย่างใช้แต่คีย์ที่มีอยู่ · `scripts/test-code-gs.js` → อัปคีย์/คำในข้อทดสอบ
6. type-check จะชี้จุดที่ยังอ้างคีย์ที่ตัดไป — ไล่แก้จนผ่าน

## 3. ภาษาหน้าจอ English

ข้อความโชว์อยู่ 3 ที่ — แปลให้ครบและสม่ำเสมอ:
- `tracking-labels.ts` — ป้าย/คำอธิบายทั้งหมด (`TRACKING_*_LABEL` · legend · `trackingDueState` label · ตัวเลือกฟอร์ม)
- `tracking-api.ts` — ข้อความ error/validate (`throw new Error('…')` · `validateTracking*`) · `tracking-csv.ts` หัวคอลัมน์ CSV + ตัวจัดวันที่ (`th-TH` → `en-US`)
- `Code.gs` — `TYPE` / `STATUS` / `PRIORITY` (คำในชีต + dropdown) · ข้อความใน `fail('…')` · ข้อความ log `'ย้ายสถานะ: '` → `'Status: '`
  (ถ้าเปลี่ยนข้อความ log ต้องแก้ `statusLogMessage` ใน `tracking-api.ts` ให้ตรงด้วย — โหมดตัวอย่างเขียนข้อความเดียวกัน)
- `setup-guide.md` แปลถ้าผู้ใช้ปลายทางอ่านอังกฤษ · comment ในโค้ดตามมาตรฐานของโปรเจกต์
- ภาษาไทยเดิมเก็บเป็น alias ไว้ใน parser ได้ ไม่เสียหาย

## 4. ไม่เอาช่องเสริมบางช่อง (deadline · release · module · blocks · link)

**ซ่อนในหน้าจออย่างเดียว** (ฟอร์ม · การ์ด · กล่องรายละเอียด · ตัวกรอง · มุมมองตามรอบส่งงานถ้าตัด release · CSV ถ้าต้องการ)
ไม่ต้องแก้ type / Code.gs / ชีต — ช่องว่างไม่มีผลเสีย และวันหลังเปิดกลับได้ทันที
ตัด `release` → ซ่อนปุ่มมุมมอง "ตามรอบส่งงาน" ด้วย · ตัด `dueAt` → ไม่ต้องโชว์ป้ายเลยกำหนด

## 5. กติกาเก็บชื่อ

| ตัวเลือก | หน้าเว็บ | Code.gs |
| --- | --- | --- |
| คอมเมนต์ + สร้าง/แก้ (ค่าเริ่มต้น) | ช่องชื่อในกล่องคอมเมนต์ + ฟอร์ม | ไม่ต้องแก้ |
| เฉพาะคอมเมนต์ | ตัดช่อง "ชื่อผู้บันทึก" ออกจากฟอร์ม · เรียก `createTrackingItem(input, '')` / `updateTrackingItem(item, changes)` | ลบบรรทัด `if (!author) return fail('กรอกชื่อผู้บันทึก')` ใน `doPost` (createItem) |
| ไม่เก็บชื่อเลย | ตัดช่องชื่อทั้งคอมเมนต์และฟอร์ม · ส่ง `author: ''` | ลบบรรทัดข้างบน + ใน `addComment` เอาเงื่อนไข `!author` ออก (เหลือตรวจความยาว) |

ไม่ว่าแบบไหน: **ห้ามเติมชื่อให้/จำชื่อไว้ในเครื่อง** (ผู้ใช้จริงไม่เอา — เหตุผลใน SKILL.md) · ลาก/ซ่อนไม่ถามชื่อ
อัปข้อทดสอบใน `test-code-gs.js` ที่เช็คว่า "สร้างต้องมีชื่อ" / "คอมเมนต์ต้องมีชื่อ" ให้ตรงกติกาใหม่

## 6. ชื่อบอร์ด / path

- ชื่อบนหัวหน้า + `<title>` หน้าเว็บ — ในหน้าจอเท่านั้น
- path — route ของแอป + ลิงก์ `?item=` ที่ผู้ใช้ส่งกัน + ตาราง SPA fallback (ถ้าโฮสต์ตั้งแบบระบุ path)
- ไม่ต้องแก้ Code.gs
